Quick reference

Hooks and DOM timeline

Choose a hook by the external system and the required timing.

One update

  1. RenderCall components. Read state snapshots. Build React elements. Do not touch the DOM.
  2. InsertionuseInsertionEffect lets CSS-in-JS libraries insert styles. Do not rely on refs or schedule state here.
  3. CommitReact mutates the DOM and assigns refs.
  4. Layout EffectsOld cleanup, then new useLayoutEffect setup. DOM exists; paint is blocked.
  5. PaintThe browser may calculate layout and update pixels.
  6. Passive EffectsOld cleanup, then new useEffect setup. Usually after paint; interaction timing has exceptions.

Selection matrix

Need Use Reason
Focus or scroll after a click Event handler + useRef The action has a direct user cause; no Effect is needed.
Subscribe, connect, or control a widget useEffect Synchronize an external system after commit.
Measure and correct before pixels appear useLayoutEffect The DOM must exist and paint must wait.
Expose focus/select from a component useImperativeHandle Expose a small imperative component API.
Read current values without reconnecting useEffectEvent Keep non-reactive event logic separate from Effect lifetime.
Insert dynamic CSS from a library useInsertionEffect Library-only timing before layout Effects.

One Effect's lifecycle

mount:            setup(current values)
dependency change: cleanup(old values) → setup(new values)
unmount:          cleanup(last values)

Strict Mode development mount:
setup → cleanup → setup

Dependency rule

Dependencies are every reactive value read by setup and cleanup. React compares each value with Object.is. The dependency list describes the Effect; it is not a scheduling preference.

Sources: useEffect, useLayoutEffect, Lifecycle of Reactive Effects, and Manipulating the DOM with Refs.
