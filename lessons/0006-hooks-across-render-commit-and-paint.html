Lesson 6 · Hooks and DOM lifecycle · 30 minutes

Hooks across render, commit, and paint

Effects do not make components “live.” They synchronize committed React UI with systems outside React.

← Lesson 5: State is a snapshot

Tangible win Given DOM-related code, place it in an event handler, useEffect, useLayoutEffect, or a ref—and explain the timing.

1. Hooks are not one lifecycle

A component function runs during render. Every Hook call is part of that function call, but Hooks have different jobs:

  • useState and useReducer return this render's state snapshot and a setter.
  • useRef returns a stable container. React assigns DOM refs during commit.
  • useMemo and useCallback cache render-time values. They are performance tools, not lifecycle callbacks.
  • Effect Hooks register synchronization that React starts and stops around commits.

Do not read “Hook” as “runs after render.” Most Hooks run while React calls the component.

2. The commit timeline

  1. Render React calls components. State is a snapshot. Refs still describe the previous commit. Render must stay pure.
  2. Insertion useInsertionEffect gives CSS-in-JS libraries an early style-insertion point. Application code rarely belongs here.
  3. DOM commit React creates, removes, and updates DOM nodes, then assigns DOM refs.
  4. Layout Effects React runs old useLayoutEffect cleanup, then new setup. The DOM is current. Browser paint is blocked.
  5. Browser paint The browser may calculate layout and update pixels.
  6. Passive Effects React runs old useEffect cleanup, then new setup. This is usually after paint.

useEffect timing has interaction-related exceptions: React may run it before paint so an event system can observe the result. If visual work must block paint, use useLayoutEffect. Do not depend on “Effect always means after paint.”

3. One Effect starts and stops synchronization

Component language—mount, update, unmount—is useful, but one Effect has a smaller lifecycle: 

first relevant commit:
  setup(current values)

commit with changed dependencies:
  cleanup(old values)
  setup(new values)

unmount:
  cleanup(last values)

Cleanup does not mean “the component unmounted.” It also runs before that Effect starts again with changed dependencies. The cleanup closure sees values from the render that created it. 

useEffect(() => {
  const connection = connect(roomId);

  return () => {
    connection.disconnect();
  };
}, [roomId]);

Changing roomId means: disconnect the old room, then connect the new room. Source: Lifecycle of Reactive Effects.

4. Dependencies describe synchronization

Every reactive value read by setup or cleanup is a dependency: props, state, and values calculated in the component body. React compares each dependency with Object.is.

Form When React restarts it
useEffect(setup) After every commit.
useEffect(setup, []) No reactive values can change its synchronization; Strict Mode still tests it in development.
useEffect(setup, [a, b]) Initial commit, then when a or b differs.

You do not choose dependencies to control frequency. You change the Effect's code so its dependency list matches what it reads. The React Hooks linter checks this cross-render contract.

5. useEffect: synchronize after commit

Use it when committed React state must stay synchronized with something React does not control:

  • A browser subscription such as resize or IntersectionObserver.
  • A network connection.
  • A timer that belongs to the component's presence.
  • A map, video player, chart, canvas, or other imperative widget.
useEffect(() => {
  function handleResize() {
    setWidth(window.innerWidth);
  }

  window.addEventListener("resize", handleResize);
  handleResize();

  return () => {
    window.removeEventListener("resize", handleResize);
  };
}, []);

Setup adds the external relationship. Cleanup removes the same relationship. Effects run only on the client. Source: useEffect.

6. useLayoutEffect: read or correct layout before paint

At layout-Effect time, React has committed the DOM and assigned refs, but the browser has not painted the result. This lets code measure a node and synchronously render a corrected position without showing the wrong position first. 

const boxRef = useRef(null);
const [height, setHeight] = useState(0);

useLayoutEffect(() => {
  const rect = boxRef.current.getBoundingClientRect();
  setHeight(rect.height);
}, []);

This can produce: render with height 0 → commit → measure → synchronous render with real height → commit → paint. The user sees only the corrected frame.

The cost is direct: layout work and state updates here block paint. Prefer useEffect unless showing the intermediate frame would be wrong. Source: useLayoutEffect.

7. A ref is the DOM handle

useRef itself does not run later. It returns the same ref object each render. React writes the DOM node into ref.current during commit and writes null when that node is removed. 

const inputRef = useRef(null);

function handleFocusClick() {
  inputRef.current.focus();
}

return (
  <>
    <input ref={inputRef} />
    <button onClick={handleFocusClick}>Focus</button>
  </>
);

Focus belongs in the event handler because the click directly caused it. Adding an Effect would hide that cause and add another lifecycle. Source: Manipulating the DOM with Refs.

8. Strict Mode tests cleanup symmetry

In development Strict Mode, React performs an extra setup → cleanup → setup cycle before the first lasting setup for layout and passive Effects. It also calls component bodies extra times to expose impure rendering.

The correct response is not a “run once” ref. Make cleanup undo setup. A connection should disconnect; a listener should be removed; a timer should be cleared; a widget should be destroyed.

9. Other DOM-related Hooks

      

        
          

            Hook
            Use
            Boundary
          

        
        
          

            useImperativeHandle
            Expose focus() or selectAll() from a component.
            Expose a small API instead of the full internal DOM node.
          

          

            useEffectEvent
            
              Let an Effect-triggered event read current props or state without restarting
              synchronization.
            
            Do not use it to hide a dependency that should restart the Effect.
          

          

            useInsertionEffect
            Insert dynamic CSS before layout Effects.
            For CSS-in-JS library authors; refs and state updates are not its job.
