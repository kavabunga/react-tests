Lesson 5 · State · 12 minutes

State is a snapshot

A render does not watch a live number. It receives a frozen copy. setState only queues the next render.

← Lesson 4: Trigger, render, commit

Tangible win Predict the next count after three setters in one click.

You already know the pipeline

Trigger → render → commit → paint. This lesson asks: what values does the render function see?

React stores state outside your function. On each render it hands you a snapshot. The count in that function body, and in event handlers created there, stays that number for the whole render. Official page: State as a Snapshot. 

const [count, setCount] = useState(0);

function onClick() {
  setCount(count + 1); // queues: next count should be 0 + 1
  setCount(count + 1); // queues: next count should be 0 + 1 again
  setCount(count + 1); // same snapshot, same 0 + 1
}
// After this click task: one render, count is 1, not 3.

Setters queue work

Calling setCount does not change count on this line. It asks React to render again later. Several setters in one event are batched into one render. Queueing a Series of State Updates.

To stack changes, pass an updater:

setCount(n => n + 1);
setCount(n => n + 1);
setCount(n => n + 1);
// Next snapshot is 3, because each updater receives the queued result.

Lab: value vs updater vs delayed log

Try all three buttons. Read the log before you guess from the UI.

  1. +1 three times (value) — three setCount(count + 1).
  2. +1 three times (updater) — three setCount(n => n + 1).
  3. set + delayed log — setCount(count + 1), then a 1s timeout. The timeout is a later task (Lesson 2). It still prints this render’s snapshot.
