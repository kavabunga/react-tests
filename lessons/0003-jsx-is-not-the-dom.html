Two objects, one look

This looks like HTML:

<button type="button">Save</button>

In a .jsx file it is not HTML. The compiler turns it into createElement. The return value is a React element: a plain description with a type and props. See createElement. 

import { createElement } from "react";

const description = createElement("button", { type: "button" }, "Save");

description instanceof HTMLButtonElement;
false

typeof description;
"object"

The root is a DOM contract

Your app already does this in src/main.tsx:

createRoot(document.getElementById("root")).render(<App />);

document.getElementById("root") is a live DOM node. createRoot tells React: manage inside this node. render accepts a React node (usually JSX), not a DOM node. See createRoot.

The first root.render clears existing HTML inside that container, then React creates DOM nodes to match the description.

What this changes in React

When a component “returns JSX”, it returns descriptions. React may later create, reuse, or skip DOM nodes so the host matches those descriptions. That later step is commit. Lesson 4 will split trigger, render, and commit.

Replace one common shortcut “JSX is HTML in JavaScript” hides the object. JSX is a description. The DOM is what the root commits.
